## Complete the source acquisition

Run from `backend/` in a network-enabled development environment:

```sh
python3 src/cities/scripts/fetch-neighbourhood-snapshots.py
```

This is an explicit maintenance command, never a dependency of build, runtime, migrations or tests. The exact Overpass and SPARQL queries are committed under `src/cities/scripts/`; expected snapshot paths are in `src/cities/data/neighbourhoods/source-manifest.json`. It saves original response bytes as `.raw.json` and a provenance envelope as `.json`, recording actual retrieval dates, licences and attribution. Commit both. Queries intentionally overfetch the envelopes of the requested regions. Review exclusions, compound candidates, duplicate features, governorate borders and the New Alamein cutoff rather than accepting every result.

Convert the residential and administrative geometry snapshots into the supplied GeoJSON evidence files. Each residential feature needs `properties.area` (greater-cairo / alexandria / port-said-region) and `properties.evidence`; administrative features need `governorateCode` or `districtSourceCode`. OSM relations require correct ring assembly and holes. Crosswalk ADM2 boundaries to OCHA P-codes manually where upstream codes are absent. Check boundary vintages; never substitute nearest-centroid assignment. Set `metadata.reviewed` only after reviewing completeness. Current files contain **no polygons**; they are explicit unavailable-evidence placeholders, not hand-drawn built-up claims.

Review every OSM feature in `reviewed-overrides.json` with an include, exclude or merge decision and nonblank review notes. An include needs an English/Arabic name, governorate code, parent source code and `parentEvidence`. Source points come from OSM/Wikidata; curated points require a `point` object with latitude, longitude and evidence. Stable identities use OSM node/way/relation IDs, WD QIDs or PUPZY slugs; do not change these when correcting a name. Duplicate district/locality names must use merge, adding aliases to the district. OSM entries can use a Wikidata tag for missing labels and aliases; an override can correct a source point only with evidence. Never promote the starter set in bulk.

`independent-names.json` is a separate candidate checklist, compiled from task examples and general knowledge, not catalog rows. It is **not independently researched or signed off**. Counts are 157 entries / 155 distinct Arabic names for Greater Cairo, 163 / 145 for Alexandria and 56 / 56 for the Port Said region. Duplicate spellings do not count toward the 150-name floor. No reduced Port Said threshold is enabled: the expanded region includes Ismailia and Damietta, so a smaller requirement has not been justified. Add researched missing names and common misspellings (currently empty), remove doubtful/out-of-scope entries and cite the research before marking it reviewed. The reviewer should scrutinize “El Gaber”, “Mubarak” and other ambiguous Port Said names; “El Hager” / “الهواجر”, “El Daraisa”, Abis numbering and Sidi Abdel Rahman in the Alexandria checklist (the latter may lie beyond the requested cutoff). These are checklist candidates, not released Cities.

Add at least 30 independently sourced GPS coordinates per area in `gps-checks.json`. Each needs latitude, longitude, `acceptableSourceCodes` and `evidence`. Do not reuse catalog coordinates to manufacture successful spot checks. The SQL integration test calls the actual repository; the offline coverage diagnostic uses great-circle distance and is not a replacement for that test.

## Build, verify and publish offline

```sh
npm run cities:build-neighbourhood-candidate
npm run cities:verify-coverage -- output/neighbourhood-cities/candidate-catalog.json
npx jest --testPathPatterns='/src/cities/' --testPathIgnorePatterns='.*\.integration\.spec\.ts$' --runInBand
npm run test:integration -- src/cities
```

The build produces a candidate combined snapshot, catalog and list of OSM rows without reviewed decisions under ignored `output/neighbourhood-cities/`. The combined snapshot embeds the ADM2 source, raw place envelopes, overrides and coverage evidence so publication/recovery still atomically handles exactly four artifacts. The original OCHA snapshot remains untouched. The verifier writes `report.md` and `report.json` and exits nonzero for missing evidence, empty grids, insufficient distinct names, missing variants, insufficient GPS checks or data-quality errors. All 500 m grid samples must be within 1.5 km of an OFFICIAL point. It handles Polygon/MultiPolygon holes and reports the ten worst measured gaps. Geographic quality checks require containing governorate/ADM2 polygons and a conservative 75 km parent-point sanity limit; investigate large desert districts if the centroid limit needs a documented override.

After all checks pass, preview and publish with the existing CLI (replace the declared count with the verified count):

```sh
npm run cities:refresh -- --candidate output/neighbourhood-cities/candidate-snapshot.json
npm run cities:refresh -- --candidate output/neighbourhood-cities/candidate-snapshot.json --official-count VERIFIED_COUNT --gov-count 27 --apply
```

The default local refresh reads the combined release snapshot. An OCHA-only `--fetch` retains the last published place sources and review evidence; updating those requires rebuilding the combined candidate.

Publish the reviewed combined snapshot through `publishReviewedRelease` (exported by `refresh.ts`), with explicit declared counts when they change. The publisher refuses a neighbourhood release without passing bundled coverage evidence or with unreviewed OSM place rows. It stages catalog, combined snapshot, generated data migration and journal together, with the existing crash-recovery protocol. It refuses an ADM2-only refresh once neighbourhoods exist, to avoid accidentally retiring all of them. Alias-only and parent changes participate in diff detection. No parallel release mechanism was introduced.

For socket-restricted development environments with local PostgreSQL/PostGIS binaries:

```sh
python3 src/cities/scripts/verify-neighbourhood-sql.py
```

This creates a disposable UTF8 cluster, uses PostgreSQL single-user mode (no socket or network), applies the current-main schema through 0064, creates User/Post district references, applies 0065 and 0066 twice, and checks UUID/reference preservation, neighbourhood nearest selection and rejection of nested/cross-governorate/retired parents. It is supplemental SQL evidence; normal Drizzle, repository and transaction integration suites still need a reachable disposable database. Never point tests at Railway or any production database.
