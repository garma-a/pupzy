# Egypt Vet Clinic release

Run from `backend/` without fetching or a database:

```
npx ts-node -r tsconfig-paths/register src/vet-clinics/scripts/build.ts
npx jest src/vet-clinics/data-quality.spec.ts src/vet-clinics/catalog.spec.ts --runInBand
```

`egypt-vet-clinics.json` is the reviewed release. `osm-egypt.json.gz` is the untouched Overpass response, deterministic gzip, with exact query, endpoint, access timestamp, attribution and compressed SHA-256 in `osm-manifest.json`. The query covers the Egypt administrative area, all veterinary amenities/healthcare, all pet shops (checked for veterinary evidence), and veterinary names across scripts. It deliberately overcollects; unrelated name matches are reported rather than counted as clinics. © OpenStreetMap contributors, ODbL 1.0.

Fetching is an explicit, separate operation: `npx ts-node -r tsconfig-paths/register src/vet-clinics/scripts/fetch-osm.ts [endpoint]`. It makes one request with `PupzyDataReview/1.0`, a bounded timeout, no automatic retries, and rejects responses containing Overpass error remarks. Fetching invalidates the reviewed decisions: review every added/changed source before rebuilding. Never overwrite the published release from an unreviewed refresh.

`reviewed-decisions.json` records one explicit inclusion/exclusion for every element. Inclusion reasons use the source name, physical amenity, operator, address/contact and other available tags together. A veterinary tag alone is insufficient. Names generated in another script are explicit faithful transliterations; existing bilingual source names are preserved. Unknown addresses remain null with `missing` origins. There are no invented coordinates, phone prefixes, opening hours or contact details. `is24Hours` is true only for explicit `24/7` hours.

`baseline-report.json` contains every rejection, merges, rejected and additional phones, and active/inactive/rejected totals for all 27 governorates. Rejections include query noise, not just proposed clinics. Elements outside all governorate polygons remain unassigned in that report; never infer their governorate from a name. Eight reviewed inclusions yield seven accepted points; the Cairo Ark node is outside every original OCHA polygon and is rejected, including its malformed phone in the issues list.

City assignment reuses the checked-in OCHA original polygons (`cities/data/neighbourhoods/ocha-cod-ab/egy_admin{1,2}.geojson.gz`) associated with the ADM2 snapshot. The JSON ADM2 snapshot itself contains representative points, not polygon geometry. Use exact containment, then the nearest Neighbourhood of that district within 2 km, otherwise the selectable district. Original polygons are used without City coverage boundary replacements. Points in nonselectable Zemam Out units are conservatively rejected; no nearest-district fallback. An OSM node representing physical premises is treated as street precision; way/relation bounding-box centres alone are approximate and cannot activate a clinic.

Phone normalization recognizes Egyptian mobile prefixes 010/011/012/015 and geographic landlines, including Cairo/Giza 02 (eight subscriber digits), Alexandria 03 (seven), and two-digit provincial area codes (seven). Bare local numbers and malformed `+010…` values are rejected. Extra valid numbers remain in the report/dataset but only the first is loaded. Deduplication uses shared valid phone (including extras), shared OSM identity, or exact normalized English/Arabic names within 150 metres; connected groups merge with their evidence retained.

`known-clinics-checklist.json` belongs to the lead. The unit gate clearly skips while absent; when present, >=90% must exactly match an active clinic in the same governorate using `normalizeCitySearch` (not substring/fuzzy matching). Stage 3 now enforces all 27 governorates by default in `data-quality.spec.ts`; no environment flag or opt-out is required or supported. A governorate without an active qualifying clinic fails unless `coverage-exceptions.json` records an explicit owner decision with governorate, owner/date, reason and research-ledger filename. The owner approved New Valley alone on 2026-11-12; its sourceable-clinic evidence gap is documented in `research-new-valley-stage3-ledger.json`. Unknown, duplicate, undocumented and obsolete exceptions fail: remove an exception as soon as that governorate gains an active clinic. Every other uncovered governorate still fails. The exception affects only release coverage validation; nearest-clinic queries remain nationwide and distance ordered. Do not add government units or weaken clinic eligibility to satisfy coverage.

Migration 0067 adds contact fields, key backfill/uniqueness and write constraints. It replaces the source enum preserving its previous labels plus WEB_RESEARCH: installed Drizzle runs all pending migrations in one transaction, so separate files containing ADD VALUE and its use would still fail. See [PostgreSQL enum transaction rule](https://www.postgresql.org/docs/current/sql-altertype.html). Phone/website constraints are NOT VALID to preserve administrator-owned historical values; PostgreSQL checks every subsequent write. Existing malformed values are never automatically rewritten except under the pristine-seed exception.

Migration 0068 is deterministic, offline and fenced by the same `city_catalog_revisions` row the Vet Clinic service/admin use. Inserts resolve `cities.source_code`, construct PostGIS points and skip existing source keys/OSM IDs. It advances the shared revision only if a row changes. A direct rerun changes neither timestamps nor revision. It updates/deactivates only original seed rows whose complete seeded payload, original City, geometry bytes, provenance, timestamps and absent location audit still match. The original City calculation is pinned to the old district catalog and the seeder's rounding cache; unknown historical City assignments fail closed. Edited or otherwise uncertain rows remain administrator-owned. The schema key backfill is additive metadata for all existing OSM rows with a known type.

The SQL generator defaults future releases to INSERT only. The stage 1–3 build explicitly enables the first-release exception and writes only 0068; after publication, allocate a new migration and leave `firstRelease` false. The custom migration files/journal were allocated by `drizzle-kit generate --custom`; generated snapshots checkpoint the current schema through `drizzle-kit/api.generateDrizzleJson` because the previous schema snapshot stopped at 0010.

## Stage 2 area-level imports

The owner's 2026-11-12 decision allows active area-level imports. `locationPrecision` is exact for sourced OSM clinic objects/first-party points, street only for a stored matching Nominatim response, and area only for the exact catalog City centre explicitly matched in the address. Addresses naming a catalog Neighbourhood use that City; an unknown neighbourhood is held unless a sourced address also names a catalog district. Never add coordinate offsets. Run `scripts/geocode-research.ts <governorate>` explicitly after importing. It sends serial Arabic then English street searches, caches every response/error in `geocodes/`, and retains area centres unless a road/building name matches the address street inside the selected catalog district polygon. Importing again replays those caches offline. See the [Nominatim search API](https://nominatim.org/release-docs/latest/api/Search/).

`research-<governorate>.json` and optional `-extra.json` are individually authored research entries. Run `npx ts-node src/vet-clinics/scripts/import-research.ts Alexandria` (or Cairo/Giza/"Port Said"), then `scripts/build.ts` and the data-quality spec after each governorate. The importer records unresolved City matches in `research-<governorate>-import-report.json`; these remain review candidates and are excluded from the released data. `scripts/research-report.ts` generates counts and reproducible random spot-check samples. Evidence snapshots are under `web-evidence/`; challenge responses are access-limit records and never clinic evidence.

0067 includes precision with a street default for existing rows; 0068 contains the first data release. Journal indices, snapshots and filename counters align. Admin map saves set exact; contact-only edits preserve location precision. Area Maps links search by localized clinic name, address and governorate; `isApproximateLocation` exposes this distinction. Shared central phones/pages do not merge explicitly documented separate chain branches; all other ordinary dedupe rules remain in force.

Field origins describe the sourced script or reviewed translation/transliteration. Generic medical descriptors are translated, brand names transliterated. `lastSeenActive` is the newest dated operating evidence; undated pages retain null, never the access/copyright/search crawl date. Old single-source dated entries before 2022 remain inactive with `stale-evidence`. Explicit hours evidence is required for `is24Hours`.

Source name spellings in both scripts are preserved in `aliases` before display-name cleanup and through merges. The independent checklist removes generic descriptors and one trailing branch qualifier, retaining pet/pets. Shared contacts across different brands require `shared-phone-decisions.json` evidence **before** deduplication; reviewed separate branches are never collapsed by that contact. Franco-Arabic digits are retained as source aliases, not English display names.

## Part E review fixes (2026-11-12)

The lead-owned checklist is a document with an `entries` array. The matcher also accepts each entry's `accept` names, folds `&` to `and`, and compares compact spacing after descriptor/branch normalization. Governorate and active status remain mandatory; the 90% threshold is unchanged.

Clinic `sources` never include geocoder/search endpoints. Street evidence stays in `coordinateProvenance` and the checked-in response cache. Arabic addresses use Arabic commas with normalized spacing. Nationwide repeated display brands (including explicit chains with variant names) use one spelling in each script and the clinic's catalog City name as qualifier. Original spellings remain aliases. Display normalization alone does not establish shared ownership.

`research-stage2-e-ledger.json` records all ten checklist investigations and unresolved evidence. `research-stage2-e-exclusions.json` archives the rejected New Sphinx shop satellite. Its URL remains on Best 4 Pets because it explicitly describes the main clinic. `distinct-address-decisions.json` records the two pre-existing Royal Helwan listings: distinct sourced streets and disjoint contacts, despite identical normalized City-level names. This narrow review affects the same-name proximity heuristic only; it cannot override shared-phone, website or OSM identity checks. No common ownership is inferred.

A qualifier can make an otherwise sourced name's origin `authored`. The double-descriptor gate therefore checks source-origin base names within that brand's reviewed input group before rejecting authored/transliterated Arabic descriptors. It does not use a general exemption list. Geocoder requests use the authored address City, avoiding query drift after a street result assigns a nearby City. Archived responses may be replayed only if they still pass the current street-name and expected-district checks; the precise response file is recorded.
